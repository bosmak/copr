# AGENTS.md

Guidance for coding agents working in this repository.

## What this repository is

A collection of **Fedora COPR RPM packaging specs** published at
<https://copr.fedorainfracloud.org/coprs/bosmak/copr/>.

It is **not** an application monorepo: there is no shared library and no build
system for the products themselves. Each top-level directory is one
self-contained RPM package with its own spec file; the only test in the repo
is the RPM smoke test (`make test`).

```
<package>/
  <package>.spec        # the RPM spec — the main artifact of this repo
  README.md             # user-facing package README (mirrors install_instructions)
  ...                   # extra files shipped as local SourceN (units, patches, scripts)
```

Top-level files:

| File | Purpose |
|---|---|
| `Makefile` | local build/lint/test entry points (`make rpm`, `make lint`, `make test`) |
| `mise.toml` | tool versions (ruff, shellcheck, yamllint, prek, uv) |
| `.pre-commit-config.yaml` | pre-commit hooks (ruff, shellcheck, yamllint, rpmlint) |
| `.yamllint.yaml` | yamllint config for the workflows |
| `README.md` | package list for the repo |
| `description` | one-line COPR project description |
| `install_instructions` | long-form COPR project instructions (per-package sections) |
| `.github/workflows/packages.yml` | builds specs → SRPMs → submits them to COPR |
| `.github/workflows/auto-update.yml` | nightly upstream version check → version bump PRs |
| `.github/scripts/vendor.sh` | vendors the dependencies of a source package into `<pkg>-vendor.tar.xz` |
| `.github/scripts/build-in-container.sh` | builds the binary RPM of a source package inside a container |
| `.github/scripts/rebundle.py` | generates and refreshes the specs of the rebundled packages |
| `.github/scripts/smoke-test.sh` | installs the built RPMs in a container and checks that they work |

## The packages

| Package | Kind |
|---|---|
| `pvpn` | prebuilt upstream binaries (Go, static), plus upstream systemd units |
| `clip-bridge` | prebuilt upstream binary (Rust) + own systemd **user** unit |
| `xwayland-satellite` | **built from source** (Rust, cargo-rpm-macros, vendored crates) |
| `steam-fix-trayicon` | **own source** in this repo (Python script + systemd user unit) |
| `solidcraft`, `artcraft-launcher`, `wordcraft`, `cadcraft`, `deckcraft`, `designcraft`, `effectcraft`, `figcraft`, `filmcraft`, `gridcraft`, `lightcraft`, `pdfcraft`, `photocraft`, `soundcraft`, `vectorcraft` | **rebundles of an upstream RPM** (Craft App Suite / solidcraft) |

Package kinds differ in the spec, so pick the pattern that matches the package
you are touching:

### 1. Prebuilt upstream binaries

- `Source0..N` point at upstream GitHub release assets.
- `%global __strip /bin/true` and `%global debug_package %{nil}` — upstream
  binaries are already stripped; re-stripping would mutate them and break
  byte-identity with upstream.
- Checksums are verified in `%prep` against upstream's `SHA256SUMS` — when
  upstream publishes one (`pvpn`, the rebundles). `clip-bridge` is the
  exception: upstream ships no checksum list, so its tarball is fetched over
  TLS and not verified.
- `%build` is empty ("we ship upstream's prebuilt binaries verbatim").
- `ExclusiveArch: x86_64` when upstream only ships x86_64 builds.

### 2. Rebundles of an upstream RPM (Craft App Suite, solidcraft)

- `Source0` is upstream's `.rpm`; `Source1` is upstream's checksum list.
- `%prep` verifies the checksum, then unpacks with
  `rpm2archive -n %{SOURCE0} | tar -xf - -C payload`.
- `%install` copies files out of `payload/` into Fedora's layout:
  licenses → `%{_licensedir}`, docs → `%{_docdir}`.
- The GUI stack (winit/xkbcommon, libX11, Vulkan) is `dlopen()`ed at runtime,
  so rpm's ELF detection cannot see it → list those `Requires` by hand.
- `%post`/`%postun` refresh the desktop, MIME and icon caches, each helper
  guarded with `command -v ... || :`.
- These specs are machine-generated and refreshed by
  `.github/scripts/rebundle.py` — edit the script, not the generated spec, if
  the change is structural.

### 3. Built from source (Rust)

- `Source0` is the upstream source tarball, `Source1` is
  `<pkg>-vendor.tar.xz` — the vendored crates, generated by
  `.github/scripts/vendor.sh` (never committed; `*.tar.xz` is git-ignored).
- The Makefile runs `vendor.sh` only for the specs that mention
  `-vendor.tar.xz`; the packages workflow runs it for every package (it
  exits early when `Source0` is not a tarball).
- `%prep` does `tar -xf %{SOURCE1}` then `%cargo_prep -v vendor`.
- `%build` uses `%cargo_build -f <features>`; `%check` uses
  `%cargo_test ... -- --lib` (integration tests need a live session).
- `ExclusiveArch` only if upstream is arch-limited.

### 4. Packages owned by this repo

- Sources are plain files committed in the package directory and referenced as
  `Source0: <file>` (local, non-URL).
- Their version is bumped by hand — they are listed in `owned_packages` in
  `.github/workflows/auto-update.yml`, so the nightly job skips them.

## Conventions in the specs

Follow the existing style exactly — the specs are reviewed by rpmlint and the
generated ones are diffed by the auto-update bot.

- Tagline: `Name`, `Version`, `Release: 1%{?dist}`, `Summary`, `License`, `URL`,
  then `SourceN` (one per upstream asset, with a comment explaining each),
  then `BuildRequires` / `Requires` / `Recommends`. A `%global` block
  (`__strip`, `debug_package`, feature flags) comes before `Name:`.
- `SourceN` URLs use `%{version}`; the tag prefix is literal (`v%{version}`).
- Comments explain *why*, not *what*. They are dense and load-bearing — keep
  that style (e.g. why `__strip` is disabled, why a `Requires` is needed).
- One comment block per group of tags, separated by blank lines.
- `%description` is plain prose, wrapped at ~72 columns.
- `%changelog` entries use `* <Day Mon DD YYYY> Name <email> - <version>-<release>`
  followed by `-` bullet lines. Bot bumps use
  `github-actions[bot] <github-actions[bot]@users.noreply.github.com>`.
- Systemd units: use `%{_unitdir}` for system units and `%{_userunitdir}` for
  user units, with the matching `%systemd_post` / `%systemd_user_post`,
  `%systemd_preun` / `%systemd_user_preun`, `%systemd_postun` /
  `%systemd_user_postun` macros. `%systemd_user_postun_with_reload` is the
  variant that also reloads the user manager after the removal.
- Post-install messages are printed with a heredoc (`cat <<EOF`) and explain
  the next manual steps; they must degrade gracefully when there is no active
  user session (container / SSH installs).
- Files are listed with the Fedora macros (`%{_bindir}`, `%{_datadir}`,
  `%{_licensedir}`, `%{_docdir}`, `%{_unitdir}`, `%{_userunitdir}`,
  `%{_sysusersdir}`, `%{_mandir}`), never hardcoded paths.
- Licenses go to `%{_licensedir}` and are listed with `%license`; upstream
  docs go to `%{_docdir}` and are listed with `%doc`.

## Commands

Tools come from [mise](https://mise.jdx.dev); `mise install` then
`mise exec -- <tool>`.

```sh
make                 # build the SRPM of every package
make srpm            # same
make rpm             # build the binary RPMs too (source pkgs build in a container)
make <pkg>-srpm      # one package
make <pkg>-rpm       # one package's binary RPMs
make <pkg>-clean     # remove build/<pkg>
make lint            # rpmlint on every spec + ruff + shellcheck + yamllint
make test            # build the RPMs and smoke-test them in a Fedora container
make clean           # remove build/ and the scratch space of the builds
make clean-tmp       # only remove the scratch space and the build leftovers
make clean-tmp-stale # also remove the stale tmp.* dirs of the system
```

`make test` installs the built RPMs into a throwaway `fedora:44` container
(`.github/scripts/smoke-test.sh`). Override the images with `TEST_IMAGE`,
`BUILD_IMAGE`, `VENDOR_IMAGE`, and the runtime with `CONTAINER`.

Prerequisites, none of which come from mise:

| Need | For |
|---|---|
| `rpmbuild` + `rpm-build` + `systemd-rpm-macros` | `make rpm` of the prebuilt and rebundled packages |
| `rpmlint` | `make lint` and the pre-commit hook (it runs as a *system* tool, so it has to be installed on the host) |
| podman or docker | `make test`, and `make rpm` of the source packages |

The source packages (`xwayland-satellite`) are the exception: their binary
RPM is built inside a `fedora:44` container by
`.github/scripts/build-in-container.sh`, which installs the spec's
`BuildRequires` there — so no Rust toolchain is needed on the host. Only the
vendoring (`vendor.sh`) needs `cargo`/`go`, or a container to do it in.

Everything builds inside `./build` (`BUILDDIR`); `~/rpmbuild` is never used.
Each package gets its own topdir (`build/<pkg>/`) so sources never mix.

The scratch space of the builds lives in `build/tmp` (`BUILDTMPDIR`), not in
`/tmp`: on Fedora `/tmp` is a tmpfs, so everything written there eats RAM
until it is removed. The scripts of `.github/scripts` create their scratch
directories with `mktemp --tmpdir`, so they follow `TMPDIR` and end up on the
disk. `make clean-tmp` removes them; `make clean-tmp-stale` also prunes the
generic `tmp.*` leftovers of the other tools (only when they are old, not a
mount point and not open by any process — the X11 and systemd sockets live
in `/tmp` too and must not be touched).

Pre-commit hooks (ruff, shellcheck, yamllint, rpmlint):

```sh
mise install
mise exec -- prek run --all-files
mise exec -- prek install     # install the git hook
```

`mise.toml` pins only ruff, shellcheck, yamllint and prek: the rpmlint hook
uses `language: system`, so it needs an rpmlint installed on the host.

## Adding a new package

1. Create `<pkg>/<pkg>.spec` and `<pkg>/README.md`.
   For a rebundle, scaffold it with the generator instead of writing it by
   hand:
   ```sh
   python3 .github/scripts/rebundle.py generate <name> <version> <rpm-url> \
       --summary "..." --license "MIT" --description "..."
   ```
   Then fill in the `%description` and check the spec by hand.
2. For a source build, add the vendor tarball handling: the spec expects
   `<pkg>-vendor.tar.xz` as `Source1`, produced by `.github/scripts/vendor.sh`.
3. Add the package to `README.md` (package list) and to `install_instructions`
   (a `### <pkg>` section with the license badge, a short description, the
   `dnf install` line and the upstream link). `install_instructions` is pushed
   to the COPR project metadata by the `update-copr` job.
4. If the package is maintained in this repo (no upstream release to track),
   add its name to `owned_packages` in `.github/workflows/auto-update.yml`.
5. Verify locally: `make <pkg>-rpm && make lint && make test`.

## CI behaviour worth knowing

- `packages.yml` discovers packages by globbing `*/*.spec`. It rebuilds
  everything when anything under `.github/` changed, otherwise only the
  packages whose own directory changed. `README.md` / `description` changes
  only refresh the COPR project metadata.
- The SRPM is submitted to COPR **only** on a push to `main`; pull requests
  build but do not publish.
- The workflow only builds the SRPM — COPR builds the binary RPM from it.
  Locally, `make rpm` builds the binary RPM itself (in a container for the
  source packages).
- `auto-update.yml` runs nightly: it derives the upstream repo and tag prefix
  from the spec's `SourceN` lines (`.../releases/download/<prefix>%{version}`
  or `.../archive/refs/tags/<prefix>%{version}`), compares the tag with the
  spec `Version:` and opens a PR on a branch `auto-update/<pkg>-<version>`.
  Rebundled packages are refreshed with `rebundle.py refresh`; everything else
  gets a plain `Version:`/`Release:`/changelog rewrite.
- The auto-update bot only knows packages whose upstream release/tag naming
  follows that convention. If a package needs custom handling, it belongs in
  `owned_packages` and is bumped by hand.

## Gotchas

- Do not commit `*.tar.xz` / `*.rpm` / `build/` — they are git-ignored.
  The ignore rules cover `*.tar.gz` and `*.zip` too, so a source tarball
  added to the repository would be silently ignored.
- The vendor tarball name is hardcoded to `<pkg>-vendor.tar.xz`, independent of
  what `Source1` is otherwise used for (e.g. `SHA256SUMS`).
- Local files from a package directory are staged into `SOURCES/` **flattened**
  by the workflow, so reference them by basename in the spec.
- Patches are applied with `%autosetup -p1` when the diff uses `a/`…`b/`
  prefixes; `.patch` files are excluded from the trailing-whitespace hook
  because their context lines are part of the diff.
- `rpmlint` must stay clean, but `make lint` does not enforce it: the
  Makefile runs it with `|| true`. The pre-commit hook is what gates the
  commits. The current baseline is one `W: no-%check-section` warning per
  spec, plus `W: invalid-url Source1` for `xwayland-satellite` (a local
  source file); rpmlint exits 0 on warnings, so the CI step stays green.
- The `smoke-test.sh` script has a per-package `case` to check that the
  application starts — add a new entry there for a new package, otherwise the
  generic `<name>-cli --version` fallback will be used.
